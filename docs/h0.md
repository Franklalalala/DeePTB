# Physical H0 prior (UniTB route)

`dptb.prior.h0` builds the atomic-charge operator
`H[rho0] = T + Vnl + Vloc[rho0]` (local part: ionic, Hartree and PBE exchange-correlation potential of the
superposed neutral atomic densities) and the overlap S of a structure on the GPU, as prior blocks for UniTB. It is
pure PyTorch and Triton; no compiled extension and no pyabacus are needed. The GF prior of the Flash route lives in
`dptb.prior.gf`; both share the operators of `dptb.prior.common`.

## Use

```python
from dptb.prior.h0.prior import H0Prior

prior = H0Prior("/path/to/h0_pair_bank_dr002_full")   # schema h0-physical-pair-bank/v1, 0.02 bohr grid
blocks = prior(z, pos, cell)                           # device tensors: atomic numbers, Angstrom positions and cell
# blocks.keys [m, 5] (i, j, Rx, Ry, Rz): the n onsite keys, then the others sorted (common.blocks.BlockKeys);
# blocks.H complex128 [m, 2w, 2w] (eV, DeePTB order, up then down
# orbitals); blocks.S float64 [m, w, w]; blocks.timing per segment; blocks.info (table store, grid spacing, FFT grid)
```

`dptb.inference.InferenceEngine("unitb", prior, ...)` runs the whole route (graph, prior, both heads, H = H0 + delta,
S, residual) on the device; see [1015-stable](1015-stable.md).

## Pipeline

| Step | Module | What it does |
| --- | --- | --- |
| Pair support | `common.neighbors`, `common.blocks` | one GPU pair search of (i, j, R) with distance <= r_c(i) + r_c(j) + 2 max r_beta (it also gives the projector queries); block keys and reverse rows (`BlockKeys`) |
| S, T | `bank`, `common.twocentre` | pair-bank cubic tables of S_L(R)/R^L, Gaunt coupling, one Triton launch per species pair |
| Local potential | `field`, `local` | FFT grid at ecutrho 480 Ry, structure-factor field and GPU PBE (`common.xc`); grid integration in 8³-point tiles: exact tile incidences, AO values evaluated on the fly in a Triton kernel, one batched GEMM per tile batch, no stored supports |
| Nonlocal + SOC | `projector`, `common.threecentre` | the nonlocal step shared with the GF prior: three-centre sums of the projector overlaps Q over shared centres, D_eff and the spin-orbit channels, on FP64 tensor cores |
| Finish | `common.finish` | the finish kernel shared with the GF prior: Hermitisation 0.5 (H + H_rev^H), spinor layout, ABACUS to DeePTB gauge, Ry to eV |

The steps, their timings next to the GF prior's and the constants are in [prior pipelines](prior_pipeline.md).

## Pair bank and table building

The bank stores per unordered species pair the S, T and projector-overlap tables, per species the orbital and
projector descriptors and the spinor KB matrix, and the real Gaunt table. Pair files are checked against the manifest
SHA256 and the physical contract once per process; decoded records stay in a host LRU (`host_bytes`).

New pairs are built on the GPU by `dptb prior build h0` (`dptb.prior.h0.build`: spherical Bessel transforms of the
ORB/UPF radial functions, `common.sbt`, `common.gaunt`, `common.pporb`) into a separate extension root; deployed
banks are never written. `H0Prior(bank, extension=EXT, build_missing=True)` builds the pairs a composition lacks
into `EXT/h0` before inference (off by default); ORB/UPF of a new element come from `species_files` or `pporb`
directories.

```bash
dptb prior build h0 --element Bi --reference /path/to/h0_pair_bank_dr002_full --out /path/to/ext --pporb /path/to/pporb
```

## Training-data readers

`dptb.prior.h0.{deeptb,io,models,constants,provenance}` read the stored h0rebuild artifacts (blocks, provenance,
units) used by `dptb.data.interfaces.h0rebuild_adapter`. Stored artifacts keep their schemas and field names.
