# Maintenance guidelines

`1013-stable` is the shared branch for feature integration, fixes, and routine maintenance. Historical branches and immutable deployments remain compatibility references; routine maintenance must not rewrite or delete them.

Keep one authoritative implementation per module. UniTB is in `dptb/nn/embedding/unitb`, historical MoE methods in `dptb/nn/embedding/legacy`, shared conditioning in `dptb/nn/conditioning`, output heads in `dptb/nn/heads`, and projector implementations in `dptb/nn/projectors`. NACF is in `dptb/nacf`; H0 reconstruction is in `dptb/priors/h0`, with explicit offline commands under `dptb h0`. Use the shared construction APIs; see [docs/architecture.md](docs/architecture.md). Do not add import aliases for moved modules. Read checkpoints with `dptb.nn.checkpoint.load_checkpoint` and keep compatibility for older checkpoints in that module; record a moved module path in its `MOVED_MODULES`. SO2 CUDA acceleration is provided by the external SO2CUDA package; its stable 0.3.0 entry point is `so2_cuda_ops.deeptb`. LoopSCF is maintained in a separate repository and depends on this branch. Update interface and version documentation for changes spanning repositories. Do not add source copies, review overlays, production logs, checkpoints, generated tables, or one-off run scripts.

Preserve the standard embedding, model-building, LMDB, sidecar, prior, training, evaluation, and postprocessing interfaces. Changes to model structure or prior layout must specify inputs, targets, units, mathematical semantics, and checkpoint compatibility. Do not resolve compatibility by manually editing user checkpoints.

Choose tests for the affected behavior using [TESTING.md](TESTING.md). Production model refactors require existing-checkpoint inference and deterministic short-training comparisons. Existing evidence may be reused for unaffected hardware benchmarks and research experiments. Do not alter or restart running production jobs for code maintenance.

Use English for public documentation, code, comments, and commit messages. Document currently available interfaces; keep internal deployment paths, run identifiers, accounts, credentials, and review history out of public documentation.
