# 全量 68 元素 / 约 3 万结构：需要扩大什么

**结论：扩大的是预计算数据覆盖与验收范围；不是按结构或元素逐个编译 CUDA。若修改 native 防护、支持边界或运行 ABI/目标架构，则安装阶段显式重编译一次，运行时继续禁止编译。** 这是当前源码和清单支持的设计判断，不是全68实测结论。

## 已核对的覆盖

- 当前 H0：59 个元素/59 个 UPF+ORB 内容身份，97 个 composition table key；store 占 9,531,704,559 bytes（8.88 GiB），158 个文件。
- 本机已有 P2 full68 manifest 是一个历史清单快照；其 68 元素中，当前59元素的 UPF/ORB 内容哈希 **59/59 完全一致**。缺9元素：Ar、He、Ir、Kr、Ne、Os、Re、Tc、Xe。
- 该68元素清单最大9个 AO 径向通道、AO lmax=3、物理 UPF projector lmax=3。两中心代码支持 l<=4；当前 local-grid r_vals[16] 容量覆盖这份清单的9通道，但 raw native 参数边界仍有缺陷，不能泛化为任意基组安全。
- `evidence/full68_comparison.json` 保存来源 manifest hash、其历史更新时间、59对匹配和68元素列表。尚未重新扫描目标29303结构的实际输入版本、组合数、FFT网格分布，因此不能保证目标数据全部等同这份清单。
- 该 P2 manifest 是 scalar-spin-trace P2 数据，不是本 H0 的 FP64 S/T/Q/D 与局域场离线格式；不能直接拷贝后宣称 H0 full68 已完成。NACF/P23 的历史缺对回退配方也不可移作 H0 默认语义。

## 分层处理

| 层 | 扩展工作 | 何时重编译 |
|---|---|---|
| CUDA 执行代码 | 同一 kernel 根据 descriptor、表和几何执行；没有按原子序数59硬编码的模板。补 local-grid 安全检查和溢出界限。 | native代码变更、Torch/CUDA ABI不匹配或目标GPU架构变化时显式构建一次。 |
| 元素数据 | 离线准备缺9元素及任何输入版本不一致的 UPF/ORB；固定 XC、电荷、自旋、NLCC、单位及 cutoff。 | 仅增加受支持的数据通常不需要。 |
| 两中心表 | S/T 的 AO–AO、Q 的 projector–AO，以及每物种 D/SOC 数据。以真实输入内容、dr、nspin、生成代码和 binary 身份选表。 | 表准备调用已有预编译算子，不能把制表说成编译。 |
| 每结构场 | ρ、ρcore、Vloc、VH、Vxc、FFT网格和几何支持依结构变化。 | 不按结构编译；不能把68元素表误当3万结构的完整势场。 |
| 批量调度 | 验收器目前写死原100例且逐结构子进程；需单独设计全量 cohort、版本、分片恢复、错误分类、资源计划和端到端计时。 | 调度层本身不要求 CUDA 重编译。 |

## 当前组合表缓存为何需要复核

`h0rebuild/offline.py:prepared_two_center` 以整套 species_data 字典+nspin 等作为 key，保存完整组合对象。相同元素对出现在不同组合中可能重复制表/保存；resident LRU 只保留2个组合对象，返回独立 deepcopy。`prepare_tables.py` 按结构遍历；`acceptance.py/new100.py` 每结构创建进程，跨结构 warm resident 复用有限。

因此不能把100例的8.88GiB直接按300倍或68/59倍推算，也不能承诺小型二进制包解决全部3万条吞吐。须先统计真实唯一输入、组合及有向对，测表字节、哈希校验、拷贝上传、核计算、CPU回传与序列化成本。

建议审查一种分片数据布局：不可变 species catalog + 按输入身份键控的 AO–AO 与 projector–AO 数值表 + 轻量组合索引；按本批需要加载，按字节预算淘汰。保存表来源完整身份，避免重复深拷贝大表引入吞吐退化；若要共享只读设备存储，必须重新证明 Python/public mutation isolation 和 stream event 生命周期，不能为了快退回暴露可变 resident。

68²=4624 是每一种有向元素对表的理论数量；S/T 只有在明确验证反向关系、打包顺序与相位后才能去重成最多2346个无序对。Q 的 projector–AO 角色不同，不能照搬 S/T 去重。仅同元素符号相同但 UPF/ORB版本、SOC/scalar或生成参数不同，不能合并。

## 最小扩展前置检查与有界验收

1. 冻结目标训练集清单与标签定义，统计实际元素/UPF/ORB哈希、原子数、基组通道/l、projector、FFT shape、磁矩/XC/charge；区别68元素全集与目标3万结构实际覆盖。不重新生成或改写原训练标签。
2. 修 local-grid 原生输入边界（包括>16通道拒绝或通用实现、设备/形状/descriptor/计数溢出），单独版本显式预编译并检查，保持旧长测冻结；其他架构须实际数值验证。
3. 在独立namespace准备缺失数据，输出覆盖与hash清单；拒绝缺表，不允许运行时编译/制表或隐式回退。
4. 对新增元素、最大基组/投影子、极端FFT、SOC/nonSOC做有界代表检查；保留现有Mn/Ca失败。全量任务的完成率、工程错误率、物理数值达标率分别统计。
5. 预算 ERROR 先单独执行配置重试；当前 mp-23435 可评估提高 field_max_work_mb 至8192MiB，但须先核实可用内存并记录新身份，未执行此方案。估算不是峰值实测，不能跳过保护或改当前正在暂停的版本。
6. 端到端稳态吞吐与存储预算确认后，再由用户授权扩到全量；本次没有启动3万结构任务或训练。
